Pipeline Day: One Batch, From Files to a Published Result

Class 11 gave you a Spark slice that agrees with the Python judge. Class 12 turns that slice into a pipeline you can run on a new batch and trust. You will write down the contract of a batch before any code runs, build the job in six stages, catch the bugs that only appear when files are joined (duplicate ids, a join that multiplies rows, ties at the cap), write the result so that a half-finished run can never be read, and prove that running the same batch twice gives the same hashes. Then a bounded AI step runs after Spark, and a held-out check decides whether its suggestions are published. No new installs this time: the Java and Spark you set up for Class 11 are enough. The model in this class is a simulated stand-in, so nothing is called and nothing is paid. Read this before class, then arrive with your project checked.

2. The big idea: write the contract first

Think of a goods-inward bay. Before a lorry is unloaded, the bay has a written list: what must be on it, how it must be packed, how much damage is acceptable, and where each crate goes. A lorry that breaks the list is turned away, with a note saying why. A pipeline needs the same list before the code runs, because after the run it is too easy to pick thresholds that make the result look good.

5. The words of a pipeline

A pipeline is a program that runs the same steps on a new set of files every day, and has to be explainable afterwards. Six words cover the contract.

WordIn plain wordsIn the Workbench
GrainWhat one row of a table means. If you cannot say it, you cannot check itThe curated table has one row per case_id, across every source
Batch idA name made from the inputs. Same files and date, same idB-c8f5e7c7c884, a hash of the three input files, the history file and the date
Attempt idA count of the times this batch has been run, kept in a fileA-001, then A-002, counted from attempts.jsonl
Rules versionA fingerprint of the rules and limits. It changes when a rule changesR-1335fcfd, written into every manifest
QuarantineRows that failed a rule, kept with a source, a row number, a category and a reasonWritten to the quarantine table. Nothing is dropped without a record
ManifestThe list of what a run wrote, with rows and a content hash for each table. It is written lastA run folder with no manifest.json is an unfinished run, and is never read

Declared, observed, derived A number in the pipeline is one of three things. A declared number is a threshold you wrote before the run (at most 5% quarantined). An observed number is counted from the data (12 of 402 rows). A derived id is computed from the inputs (the batch id). A check compares an observed number with a declared one, and the report shows both.

6. Six stages, and the bugs between them

The job runs six stages in a fixed order. After each one the class prints how many rows went in and how many came out, because a stage that quietly loses or multiplies rows is the most common pipeline bug.

1. ReadWritten schemas, row numbers
→
2. ValidateAccept or quarantine, with a reason
→
3. TransformWindow, ties, flags
→
4. JoinAggregate first, then left join
→
5. CheckBlock, warn, info
→
6. WriteStaged swap, manifest last

Block, warn, info A block check stops the batch (too many quarantined rows, a multiplied join, a missing source). A warn check lets it through but is shown in the report (shipment coverage below 80%, too many stale scans). An info check is only a number worth seeing (12 orphan notes). Which is which is declared in config/quality.toml, before the run.

7. Rerun it, bound the model, gate the result

A run you cannot repeat is a run you cannot trust. And an AI suggestion is only worth publishing if a held-out check says it is good enough. Three rules:

1. Rerun to prove itSame batch id, new attempt id, same hashes. The content hash ignores file names and row order
→
2. Model after SparkSpark stops first. The model step has a cap, a cache and a review queue, and is called only from Python
→
3. Gate before publishA held-out set that nothing was tuned on decides: PUBLISHED, or HELD with the reason
